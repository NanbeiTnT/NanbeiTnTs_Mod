# 开发路线 · Roadmap

> 产品定位：**PvP 实用模组**，对标 Lunar / Badlion 客户端的"功能聚合"形态。  
> 按右 Shift 打开设置界面，界面里逐项开关功能、调整参数。非作弊，仅客户端。
>
> 这份文件是路线图；具体有什么类、什么方法，去 [`DEV_REFERENCE.md`](DEV_REFERENCE.md) 查。

---

## 1. 整体结构

模组分五块，从上到下是"谁调谁"的关系：

| 层   | 作用                       | 玩家视角         |
| --- | ------------------------ | ------------ |
| 输入层 | 注册按键，右 Shift 触发界面        | 按一下键，菜单弹出来   |
| 界面层 | 自绘的设置界面：分类列表 + 开关 + 滑块   | 左边选类别，右边改设置  |
| 模块层 | 模块管理器 + 各功能模块（每个是一个独立开关） | 每个功能单独开/关    |
| 钩子层 | 接管游戏每帧、每次逻辑更新时的执行点       | 功能真正"起作用"的地方 |
| 配置层 | 把开关和参数存成 JSON，启动读、改动写    | 关掉游戏再开，设置还在  |

关键设计原则：**模块只关心自己的逻辑，不直接读文件、不直接画界面**。  
界面改的是模块的状态，模块状态变了由配置层统一保存 —— 这样加第 20 个功能时不用改界面和配置的代码。

## 2. 阶段计划

### P0 · 骨架（第一步，必须先做完）

目标：按右 Shift 能弹出界面，界面里有一个能开关的假功能，重启游戏后状态还在。

- [x] 键位注册（右 Shift，允许玩家改成别的键）
- [x] 设置界面骨架：可拖动的窗口、左侧分类、右侧条目（窗口居中固定，拖动待做）
- [x] 控件：开关、滑块、键位绑定（下拉选择待做）
- [x] 模块基类 + 模块管理器（注册、查找、按分类分组）
- [x] 配置读写（JSON，存到 `.minecraft/config/nanbeitnts_mod/`）

**验收**：进游戏按右 Shift 出界面 → 点一下开关 → 退出重进，开关仍是那个状态。

### P1 · 信息显示（最先做的真实功能）

只读、零风险、不需要动游戏逻辑，最适合验证渲染管线。

- [ ] CPS（左右键点击速度）
- [ ] 按键显示（WASD + 空格 + 左右键）
- [ ] 护甲耐久 / 手持物品耐久
- [ ] 坐标 + 帧率 + 延迟
- [ ] 药水效果剩余时间
- [ ] 所有 HUD 元素可拖动、可缩放、可调透明度

**验收**：进服务器打架时，屏幕上能稳定显示这些信息，不挡视野、不掉帧。

### P2 · 视觉与信息增强

- [ ] 准星自定义（形状、颜色、大小）
- [ ] 命中反馈（击中目标时的准星变化/伤害数字）
- [ ] 视距、天气、粒子、视角摇晃等"客户端侧"视觉设置
- [ ] 计分板/队伍信息整理显示
- [ ] 目标信息（看向谁、对方血量与装备）

### P3 · 操作便利（需逐个评估合规性）

- [ ] 潜行/疾跑保持
- [ ] 快捷栏锁定、物品使用防误触
- [ ] 战斗计时（连击间隔、无敌帧提示）

这一阶段每个功能都要先判断：**会不会给玩家不公平的信息或自动化优势**。判断不了的，先问。

## 3. 明确不做的

以下属于作弊范畴，无论技术实现难易都不做：

自动瞄准 / 自动攻击 / 攻击距离延长 / 判定框扩大 / 自动喝药 / 自动切换工具 / 穿墙透视箱子与实体 / 飞行与加速 / 任何绕过服务器反作弊的东西。

原因不是"做不出来"，而是这些会直接导致玩家被封号，且破坏服务器生态 —— 与"实用工具"的产品定位冲突。

---

## 4. 1.21.11 的技术风险（提前说明）

1. **渲染 API 在 1.21.9 之后被重写过**。网上绝大多数 PvP 模组教程（1.20.x 及更早）用的绘制方法在这个版本已经不存在了，  
   照抄会编译不过。这块需要按当前版本的图形接口重新写，也是整个项目最花时间的部分。
2. **右 Shift 可能被玩家绑定成潜行**。所以键位必须可改，且要在界面里提示当前绑定关系，避免"按了没反应"。
3. **界面打开不等于游戏暂停**。单机里打开设置界面要不要暂停、多人里能否边看边改，需要按 FPS 类客户端的习惯处理。
4. **模块越多，每帧开销越大**。HUD 元素不能每个都单独遍历一次，要统一收集后一次画完，否则掉帧。
